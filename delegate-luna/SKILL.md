# 指派 Luna

把母代理當成編排、決策與品管者，把 `luna_worker` 當成一次性、無狀態的執行器。每個 Luna thread 只接受一份完整工作單，完成或回報阻礙後立即結束。

## 硬性規則

1. 只委派給自訂代理 `luna_worker`；不得啟動 default、worker、explorer、Sol、Terra 或其他自訂子代理。
2. `luna_worker` 必須實際解析為 `gpt-5.6-luna` 且 `model_reasoning_effort = "max"`。若 runtime 顯示不同模型或 effort，立即停止並回報實際值；不得把同名的一般子代理當成成功。
3. 母代理必須配合 Luna 的能力調整派工。不得要求 Luna 承擔全局架構、大範圍探索、未釐清需求、跨系統取捨或長依賴鏈；先由母代理選定方向、消除歧義並拆小。
4. 每個 Luna 任務都必須單向且一次性：`母代理下達完整工作單 → Luna 執行、自驗、回報 → thread 結束`。不得依賴後續對話把任務補完整。
5. 一律以 `fork_turns = "none"` 建立新的 Luna thread。不得要求 Luna 重讀母代理、其他代理或上一個 Luna thread 的對話；所有必要資訊必須寫進本次工作單或以精確路徑指向穩定來源。
6. 不向已回報的 Luna thread 發 follow-up。若結果不合格或遇到阻礙，母代理先驗收、歸因並重寫完整工作單，再建立新的 `luna_worker` thread。
7. 所有實質執行工作交給 Luna。母代理只做必要的目標理解、全局取捨、依賴排序、工作單設計、結果驗收、失敗歸因與最終整合。
8. 若 Luna 無法啟動、工具不支援自訂角色或權限不足，停止並明確回報阻礙。除非使用者另行同意，不得改用其他模型，也不得由母代理悄悄代做。
9. 遵守原任務的權限、安全與破壞性操作限制；本技能不擴張授權。

## 可攜代理設定

- 本 Skill 內附 `assets/luna-worker.toml`，作為移轉與安裝用的代理設定來源。
- Codex 不會直接從 Skill 目錄載入自訂代理。個人安裝必須放在 `~/.codex/agents/luna-worker.toml`；專案限定安裝則放在該專案的 `.codex/agents/luna-worker.toml`。
- 搬移到另一個 Codex 環境時，先安裝整個 Skill，再把內附 TOML 複製到其中一個正式代理目錄，重新啟動 Codex，並確認實際 runtime 為 `gpt-5.6-luna`、`max`。
- 若正式代理目錄已有同名檔案，先比較內容；未取得明確授權不得覆寫。Skill 內的檔案是可攜來源，正式代理目錄中的檔案是執行時載入副本。

## 工作流程

### 1. 母代理先完成全局判斷

- 確認真正的交付成果、成功條件、限制與排除範圍。
- 保留全局架構、跨任務取捨、相依關係與最終驗收責任。
- 只有會實質改變成果方向的缺口才詢問使用者；其餘採取不偏離意圖的合理假設。
- 在派工前決定 Luna 不應自行決定的事項，不把選方向包裝成執行任務。

### 2. 拆成 Luna 適合的一次性子任務

適合直接交付：目標確定、上下文有限、步驟可列舉、輸出格式固定，且能用明確證據驗收的實作、檢查、整理、轉換、測試或局部研究。

不適合整包交付：開放式目標探索、全局架構決策、大量互相耦合的檔案或系統、仍有多種合理解讀的需求，或需要持續記住大量隱含脈絡的工作。

每個子任務必須：

- 只有一個可用一句話描述、可獨立驗收的結果。
- 優先只涵蓋一個模組、一次轉換、一組同類檢查或一個可獨立驗收的改動面。
- 明列必要輸入、固定決策、精確路徑、可做與不可做的邊界。
- 指定交付物、輸出格式、通過條件與相稱的驗證方法。
- 標示前置依賴，以及是否可與其他任務安全並行。
- 不要求 Luna 猜測需求、重新理解整個專案或自行擴張目標。

若任務仍包含多個方向、大量全局取捨或無法明確驗收，繼續拆小。不要只按檔案數切割而破壞工作完整性。

### 3. 編寫自足工作單

每次使用 `fork_turns = "none"`，並把以下欄位完整寫入派工訊息：

```text
任務編號／名稱：
唯一目標：
必要背景與已確定決策：
必要輸入／精確路徑：
工作範圍：
禁止事項／不得自行決定的事項：
交付物與輸出格式：
通過條件：
驗證方法：
阻礙處理：不要提問或等待補充；無法繼續時，以 BLOCKED 回報缺少什麼、已查證什麼及最小解法。
最終回報必含：PASS／BLOCKED、完成內容、證據、異動檔案、測試結果、未解風險或阻礙。
```

派出前由母代理執行工作單自檢：

- Luna 不看先前對話，是否仍能知道要做什麼？
- 是否只有一個合理執行方向？
- 所需輸入是否存在且能直接定位？
- 可否不詢問母代理就完成並驗證？
- PASS 與 BLOCKED 是否都有客觀判準？

任一答案為否時，不得派出；先補齊或拆小。

### 4. 啟動一次性 Luna thread

- 指定自訂角色 `luna_worker`，不可只把一般子代理的 task name 命名為 luna_worker。
- 使用 `fork_turns = "none"`，不傳遞母代理對話歷史。
- 第一個 Luna thread 啟動後，若介面提供 runtime metadata，確認 `agent_role = luna_worker`、`model = gpt-5.6-luna`、`effort = max`。
- 只有彼此獨立、沒有順序依賴，且不會同時修改相同檔案或共享狀態的任務才並行。
- Luna 可在該次執行內使用多個工具步驟、自我檢查與修正；「一次性」是指不依賴跨對話補充，不是只能執行一個動作。
- Luna 回傳一次最終 PASS 或 BLOCKED 後，該 thread 即終止；若介面支援關閉已完成 thread，予以關閉。

### 5. 母代理驗收

不要把 Luna 的 `PASS` 當成驗收結果。母代理必須依原始目標與工作單獨立檢查：

- 成果、範圍及禁止事項是否完全符合。
- 檔案、命令、測試或其他證據是否可核對。
- 是否遺漏邊界案例、相依任務或未解風險。
- 多個結果是否衝突、重複或留下整合缺口。

通過才接納；未通過則進入失敗檢討，不向原 thread 追問或補派。

### 6. 失敗檢討與重新派工

只有出現 BLOCKED、驗收失敗或需要重工時才執行檢討。先用證據判定主要原因，不要一律歸咎 Luna：

1. **工作單缺陷**：缺少輸入、決策、路徑、邊界、輸出格式或驗收標準；用語仍有多種合理解讀。
2. **任務與 Luna 不匹配**：範圍過大、耦合太高、依賴太長，或仍要求全局探索與取捨。
3. **Luna 執行缺陷**：工作單已清楚自足，但 Luna 漏做、違反邊界、未驗證或證據不足。
4. **工具／環境阻礙**：權限、工具、相依服務、檔案狀態或外部系統使任務無法完成。
5. **母代理驗收／整合缺陷**：派工各自正確，但拆分、順序、衝突管理或整合標準有誤。

產生一份精簡檢討：

```text
失敗現象與證據：
主要原因分類：
責任位置：工作單／任務切分／Luna 執行／環境／母代理整合
下一份工作單要改什麼：
是否暴露可重複的 skill 缺口：是／否
若是，建議新增或改寫的規則：
```

處理原則：

- 工作單、任務匹配或整合有缺陷時，由母代理承擔修正責任，重新拆分或補齊決策。
- Luna 執行有缺陷時，把漏項改成更可機械驗收的明示要求；不要只寫「請更仔細」。
- 環境有阻礙時，先在授權範圍內排除；無法排除就回報使用者，不得假裝成功。
- 需要重派時，建立全新的 `luna_worker` thread，提供重新撰寫的完整工作單；不得引用舊 thread 或叫新 Luna「接著做」。
- 只有可跨任務重現的結構性缺口才列為 skill 改善候選。個案內容留在本次任務，不塞入通用 skill。
- 不在一般任務中自行改寫本 skill。將改善候選與證據回報使用者；只有獲得明確授權後才修改並驗證 skill，避免規則因單次偶發錯誤無限膨脹。

### 7. 整合交付

- 等待所有必要 Luna 任務通過母代理驗收後再交付。
- 由母代理整合、去重並解決結果間的矛盾。
- 最終回覆先說成果，再列必要驗證、限制與未解事項。
- 若曾失敗或重派，附上精簡根因與 skill 改善候選；成功且無重工時不產生形式化檢討。
- 不把 Luna 的原始長篇輸出整段轉貼給使用者，只保留支撐結論的證據。

## 小任務與例外

- 任務小到不需要拆分時，仍建立一個範圍明確、一次性的 Luna 子任務；本技能觸發後不得由母代理直接代做實質工作。
- 任務本質上無法安全委派，例如需要使用者即時選擇或新的外部權限時，母代理先處理阻礙；條件齊備後再建立新的 Luna thread。
- 使用者明確要求其他模型或允許母代理親自執行時，以最新指示為準，並說明已偏離本技能的 Luna-only 模式。
